# Tabularium

[English](README.md) · 中文 · [Lingua Latīna](README.la.md)

Tabularium 是一个自部署的笔记库同步服务器，采用端到端加密，并配有连接它的 Obsidian 插件以及网页端控制台。笔记在每台设备上加密后才上传；服务器把它们存在 CouchDB 中，无法读取内容。不开放注册：账户由管理员创建。

网页端还支持在线云笔记，云笔记可以在浏览器中阅读和编辑笔记，可以以多种形式（公开查看或需密码查看、限时有效的链接或长期有效的链接）将笔记分享到公共互联网上，你还可以将你的笔记发送到你的 Kindle 设备上。将笔记分享到互联网、将笔记推送到 Kindle 功能在 Obsidian 插件同样支持。

除同步服务外，服务器网页端还提供笔记服务器管理、定时备份，以及 AI 管理员 Tabularius（笔记库书记员），笔记库的所有者可以为单个笔记库开启它。它支持接入多家 API（OpenAI、Anthropic、Google Gemini、DeepSeek）以及本地部署模型的推理引擎（vLLM、Ollama、TensorRT-LLM）；配方可以设置各提供商接口接受的全部参数。你还可以为书记员配置 RAG 检索，只要你部署了 RAGFlow 服务器。

## 功能

### 同步

同步采用 CouchDB 的复制协议。客户端的同步核心是插件仓库中的 `@tabularium/sync-core`，Obsidian 插件、云笔记和命令行客户端共用它。

- **数据模型**：每个笔记库在服务器上是一个独立的 CouchDB 库，每台设备在本机也有一个数据库。文件的改动先写进本机数据库，再与服务器双向复制。一篇笔记存为一份元数据文档（`f:` 开头，记录它由哪些分块组成）和若干内容分块（`h:` 开头，按内容命名，相同的分块只存一份），所以改一处只传变化的分块。
- **实时**：客户端订阅服务器的变更流（`_changes` 的连续流或长轮询），其他设备的改动几秒内到达。插件的同步方式可选实时、定时或按事件（启动、保存、切换文件时）；实时同步可以按设备暂停，暂停期间的编辑留在本机，恢复或「立即同步」时上传。
- **冲突**：两台设备改了同一篇笔记，改动在不同的行时自动合并；改在同一处时保留各个版本。插件可以设为保留较新的版本，云笔记中有并排的冲突视图，可选一个版本或编辑合并后的内容。插件的右键菜单「历史版本」列出一篇笔记在本机的各个版本，可以对比、复制或回到某个版本。
- **网关**：客户端连接 `/sync/<笔记库 ID>/`，网关把它映射到服务器生成的物理库名。它只放行复制所需的接口（变更流、`_revs_diff`、`_bulk_get`、`_bulk_docs`、`_local` 等），读取每次写入的正文，只接受加密并混淆路径后的文档形态，逐条拒绝其他写入。每台设备有请求频率限制，长连接 5 分钟后由客户端重连。
- **账户与设备**：账户由管理员在网页上创建，初始密码首次登录时修改。每个客户端（一个 Obsidian 库或一个浏览器配置）登录后获得自己的设备凭据，有效期 30 天，剩余不足 15 天时自动续期；30 天没用过的设备失效。设备在「账户设置 → 设备」中按客户端列出，显示最后同步时间，可以改名或撤销，撤销后它的同步连接立即断开。
- **重建笔记库**：需要用某台设备的笔记覆盖服务器时，笔记库所有者先为这台设备授权 15 分钟的窗口。窗口内的重建由网关改为新建一个物理库并切换过去，原库保留、可以切回；其他设备随后显示「笔记库已锁定」，各自从服务器重新获取，全部获取后由所有者解除锁定。
- **命令行客户端**：同一个同步核心还打包成命令行客户端，可以在服务器上把笔记库镜像为一份明文文件夹，供 git 审计或脚本使用。

### 加密

- 笔记在设备上加密后才写进同步数据库。E2EE 密码短语经 PBKDF2-SHA256（310,000 次迭代）派生出主密钥，再用 HKDF 为每个分块派生密钥，以 AES-256-GCM 加密。PBKDF2 的盐随笔记库存在服务器上，密码短语只保存在各自的设备上。
- 路径混淆把文件路径也加密，服务器上的文档 ID 和元数据中看不到文件名与文件夹结构。
- 连接 Tabularium 时，插件强制开启加密（E2EE V2）和路径混淆；服务器只接受这种形态的文档，所以服务器上保存的始终是密文。服务器能看到的是账户、设备、请求时间与流量。
- 插件 `data.json` 中的同步凭据和密码短语用一个只存在本机的密钥加密；连接绑定登录时的 Obsidian 笔记库，插件文件夹被复制到别的笔记库时，连接在启动时清除。
- 为某个笔记库开启 Tabularius 时，服务器才持有这个笔记库的密码短语（用服务器密钥加密后存放）和一份明文副本，开启前页面会说明；关闭时这些一并删除。

### 文件排序

在笔记库根目录写一篇 `Collation.md`，正文里的缩进列表就是文件列表的顺序：

```markdown
- 项目计划 —— 先读计划
  - 需求
  - ...
  - 归档
- 会议记录
- Collation
```

- 一项一个文件或文件夹，缩进表示所属文件夹；列出的项目按列出的顺序排在前面，没列出的按原来的顺序排在后面，`...` 表示没列出的项目插在这里（上例中「归档」总在最后）。
- ` —— ` 后面是给人看的说明，阅读时收进名称后的 ⓘ 图标。项目可以写成 `[[名称]]`，点击打开；列表以外的正文随便写。
- 子文件夹可以有自己的 `Collation.md`，覆盖上级对这个文件夹的设定。
- 文件列表的右键菜单「排序」中有「移到最前」「移到最后」（直接改写列表）和「在 Collation.md 中定位」。
- 排序只改变显示顺序。规则笔记随普通同步到达各设备，Obsidian 文件列表、云笔记的文件树、文件夹分享的目录都按它排列。

### 云笔记

网页上的笔记客户端，在没装 Obsidian 的电脑上阅读和编辑笔记。

- 在浏览器里同步和解密，每个浏览器算一台设备。笔记存在浏览器的私有文件系统（OPFS）和 IndexedDB 中，密码短语只在页面内存里；第一次打开时取回整个笔记库，之后只同步变化的部分。
- 阅读的显示接近 Obsidian：callout、任务列表、表格、KaTeX 公式、`==高亮==`、Mermaid 图，代码块按语言着色（六十多种语言）。
- 编辑器有即时渲染（像 Obsidian 的实时预览）、源码和分屏预览三种方式，选中文字时浮出格式工具条，「+」菜单插入表格、代码块、各种 Mermaid 图、公式、callout 和附件。停止输入 2 秒后自动保存，标题旁显示「本地已保存」「待上传」「已同步」「冲突」。
- 新建、重命名、移动、删除笔记和文件夹；改名或移动时，其他笔记中指向它的 wikilink 和 Markdown 链接随之更新。附件可以拖进编辑器。
- 页面由浏览器缓存，完整获取过的笔记库在断网时也能解锁、浏览和编辑，联网后上传离线期间的修改。
- 「清除本地数据」删除这个浏览器里的副本并撤销设备；退出登录时可以选择一并清除。

### 分享

把一篇笔记或一个文件夹分享到互联网，访客不需要账户，在浏览器里只读阅读。云笔记的「⋯」菜单和 Obsidian 的右键菜单都有「分享…」。

- **两种方式**：加密链接（默认）在设备上加密后上传，密钥只在链接 `#` 后面的部分里，服务器保存的是密文；公开网页以明文保存，可以选择允许搜索引擎收录（页面带标题和开头约 160 字的描述）。
- **链接**：`https://<域名>/s/<地址>`，地址可以自己起，也可以随机生成。
- **有效期**：1 天、7 天、30 天、长期有效或到指定日期；到期后服务器删除分享的内容。
- **访问密码**：可选。加密链接的密码参与解密，公开网页的密码由服务器校验。
- **引用的笔记与附件**：对话框列出分享内容引用到、但不在分享范围里的笔记和附件，可以逐层勾选；嵌入的图片和附件默认一起分享。没有勾选的引用在分享页上显示为「无访问权限」，隐去名称、路径和链接文字。
- **文件夹**：文件夹里的所有笔记和附件都在分享内，目录按 `Collation.md` 排列，每篇笔记有固定的地址。
- **自动更新**：分享范围内的文件被修改、新建、改名或删除后约 10 秒，分享重新生成，链接不变。由最后保存这个分享的设备负责更新；被分享的笔记改名或移动时分享跟随，删除时分享撤回。
- **禁止复制**（可选）：分享页把正文、公式、图表和图片绘制成画布图像，公开网页的内容也加密传输；选择、复制、右键、拖拽、打印和常用的开发者工具快捷键都被拦截。
- **显示**：分享页按分享者自己的配色显示，渲染与云笔记相同，包括 Mermaid 图。
- **管理**：「账户设置 → 我的分享」列出自己的全部分享和访问次数，可以修改有效期、撤回或清理失效分享；管理员在「管理 → 分享」中管理所有人的分享。

### 敏感秘密内容

在编辑器里选中密码、令牌、账号这类文字，点格式工具条的「敏感」或运行同名命令，这段文字前后就加上不可见的标记字符。阅读视图与原文一样；在 Obsidian 的编辑器模式下可见敏感标记的文字为带底色和红色眼睛角标，光标一步跨过标记。再应用一次取消标记；选中多行时逐行标记，Markdown 语法保持原样。

敏感秘密内容的标记字符是 Unicode 中三个不可见的数学运算符：U+2061（函数应用）、U+2062（不可见乘号）、U+2063（不可见分隔符）。开始标记按 U+2061 U+2062 U+2063 的顺序排列，结束标记倒过来，为 U+2063 U+2062 U+2061；一段标记不跨行，缺少结束标记时一直遮盖到行尾。

- **分享**：「脱敏」默认开启，标记的内容在离开设备之前就替换为 `••••••`（代码块中的也一样），服务器和访客拿到的都是占位符。对话框显示这次涉及几处。
- **Tabularius**：标记的内容发给模型前换成 `[REDACTED]`，提案写回笔记时还原为原文。
- **发送到 Kindle**：显示原文，去掉标记字符。

### 发送到 Kindle

插件和云笔记在本机把笔记生成 EPUB 3（标题、二级标题目录、PNG/JPEG/GIF 图片、代码块，经 EPUBCheck 检查），由服务器用管理员配置的 SMTP 账户发到用户的 Kindle 邮箱。可以发一篇笔记、一个文件夹（子文件夹各成一部分），或多选后每项各发一本书。服务器检查 Kindle 邮箱的域名、50 MB 上限和每人每日次数，发送记录只存时间、文件名、大小和结果。

### Obsidian 插件

插件 id 为 `tabularium`，需要 Obsidian 1.13 或更新的版本，桌面和手机都可用。

- **登录**：输入服务器地址、用户名和密码，选择或新建笔记库，填写 E2EE 密码短语，插件签发设备并写好连接设置。已有笔记的设备可以选择以服务器为准或比较时间。
- **设置页**：连接、同步、文件排序、发送到 Kindle、编辑器、外观、维护、帮助，每一项都能用 Obsidian 设置的搜索找到。帮助页和版本历史随插件提供。
- **维护**：从服务器重新获取、用这台设备覆盖服务器、解除锁定、诊断报告、查找不完整的文件、冲突全部保留较新的版本。危险操作用同一种确认框，写明对其他设备的影响。
- **编辑**：与云笔记相同的格式工具条（含「敏感」）和右键「插入」菜单，每一项都是可以绑定快捷键的命令。
- **断链**：「检查断链」列出指向不存在文件的链接，按同名文件给出修复目标；「自动修复断链」可以在一台常开的设备上打开。
- 文件排序、分享、发送到 Kindle 和暂停实时同步都在文件列表的右键菜单中。

### Tabularius（书记员）

按笔记库开启的 AI 笔记管理员，网页入口是「书记员」。

- **问答与检索**：服务器为开启的笔记库运行一个托管客户端，同步一份明文副本并建立索引（SQLite FTS5 全文检索加可选的 embedding 语义检索，两路结果合并）。回答逐字显示，引用的笔记可以点击，在云笔记中打开。
- **整理与提案**：整理、改名、移动、删除笔记时，它先提交一个提案，列出每个文件的 diff；你审阅后整批应用或放弃。应用前逐个核对文件有没有在别处被改过，移动和改名时自动更新指向它们的链接，修改时间为应用时的时间。整理的规范写在服务器和笔记库的提示词里，可以包括维护各文件夹的 `Content.md` 和根目录的 `Collation.md`。
- **提供商与配方**：Anthropic、OpenAI、Google Gemini、DeepSeek，以及本地的 vLLM、Ollama、TensorRT-LLM。模型列表从提供商的接口读取。配方是「模型 + 参数 + 补充提示词」的组合，参数表单列出每家官方接口接受的全部参数；对话可以在配方之上临时微调。
- **对话**：图片、文本文件和 PDF 附件；项目分组与归档；跨对话的记忆（按账户保存，在页面上管理）；检索以前的对话；长对话的上下文由各提供商的方式压缩或截断。
- **联网核实**：逐条核对笔记中的版本、命令、参数和链接，给出相符、过时、不符或无法核实，并列出来源。Claude、OpenAI、Gemini 用自带的搜索，其他模型用服务器的 SearXNG。
- **沙箱与 SSH**：在一次性容器中运行笔记里的代码和命令（资源与时长受限，默认断网）；经 SSH 在管理员登记的主机上执行命令，范围由权限档位决定。
- **权限档位**：只读、受限（白名单命令与登记的内网地址）、完全，服务器规定最高档。登记为「禁止」的主机在任何档位都连不上；改笔记始终经过提案。
- **发送范围**：排除的路径不进索引、不发给提供商；屏蔽规则（RE2 正则，默认覆盖常见 API 密钥、私钥和 `password:` 一类的值）把凭据换成 `[REDACTED]`。
- **本地知识库**：可以接入 RAGFlow 的 MCP 检索，embedding 可以改用本机服务。

### 网页应用与管理

一个登录页和统一的外壳：首页、云笔记、书记员、账户设置，管理员另有「管理」。

- **首页**：笔记库状态、各设备的最后同步时间、占用、最近的笔记与对话、服务器摘要。
- **账户设置**：笔记库（重建授权、解除锁定）、设备、我的分享、Kindle 邮箱、修改密码，以及界面（语言、配色：樱粉、森林、薰衣草和多套自定义配色）。
- **管理**：账户、笔记库、设备、用量、运行状态、操作记录；「服务器设置」（发信与 Kindle、分享、会话与设备有效期、频率限制、操作记录保留）；「LLM 设置」（提供商、配方、提示词、embedding、联网、权限上限、SSH 主机、沙箱）；「分享」；「备份」。所有运行设置都在这里修改，立即生效。
- **定时备份**：服务器在线做增量备份，按日、周或月，可设时间、时区、保留份数和全量间隔；每个备份点校验大小与 SHA-256 后发布，失败时在运行概览中提示。
- 插件和所有网页都有英文、中文、拉丁语三种界面。

## 仓库

这是父仓库。服务器和插件是子模块，各有自己的仓库：

| 路径 | 仓库 | 内容 |
| --- | --- | --- |
| `apps/server` | [Tabularium-Server](https://github.com/Violaria/Tabularium-Server) | Node.js 网关、SQLite 应用库、网页应用、Tabularius |
| `apps/obsidian` | [Tabularium-Obsidian](https://github.com/Violaria/Tabularium-Obsidian) | Obsidian 插件；云笔记和服务器所用命令行客户端的源码也在这里 |
| `deploy/` | 本仓库 | Compose 文件，备份、恢复、升级与回退工具，发布包构建 |
| `tests/` | 本仓库 | 跨组件的测试：真实客户端同步、Tabularius 端到端、备份、发布包 |

服务器镜像由两个子模块共同构建，所以构建和测试都在本仓库中进行。

## 构建

需要 Node.js 24.10.0 和 npm 11.6.1（见 `.nvmrc` 和 `package.json` 的 `engines`）；服务器和大部分测试需要 Docker 与 Compose 2.24 或更新版本。

```bash
git clone --recurse-submodules git@github.com:Violaria/Tabularium.git
cd Tabularium
npm run bootstrap   # 安装工作区和插件的依赖
npm run build       # 服务器、插件 main.js、CLI
npm run check       # 全部类型检查与 lint
```

测试：

| 命令 | 覆盖范围 |
| --- | --- |
| `npm run test:server` | 网关与 API，连接真实的 CouchDB |
| `npm run test:server:browser` | 无头浏览器中的管理控制台 |
| `npm run test:unit` | 插件单元测试 |
| `npm run test:tabularius` | Tabularius 端到端，模型提供商为脚本化替身 |
| `npm run test:backup` | 备份、恢复与定时备份 |
| `npm run test:gateway` | 真实客户端的同步回归（需要桌面版 Obsidian） |
| `npm run test:release` | 用构建好的发布包做一次全新安装 |

## 本地运行

```bash
cp deploy/local/.env.example deploy/local/.env
# 设置三个密码；管理员初始密码至少 12 个字符
docker compose --env-file deploy/local/.env -f deploy/local/compose.yaml up --build -d --wait
curl http://127.0.0.1:3000/health/ready
```

打开 `http://127.0.0.1:3000/`，以 `admin` 登录并修改密码。运行设置（发信、分享、AI 提供商、备份）都在网页上配置；`.env` 只放容器启动前就需要的内容。

## 发布与安装

`npm run release` 生成 `release/<版本>/`：服务器镜像的 tar 文件、插件的 zip、部署目录（`compose.yaml`、`couchdb.ini`、`.env.example`、`backup/`）、第三方许可证和校验和。在目标主机上：

```bash
cd release/<版本>
sha256sum -c SHA256SUMS
docker load -i tabularium-server-<版本>.tar
docker tag tabularium-server:<版本> tabularium-server
cd deploy
cp .env.example .env    # 填写密码和 TABULARIUM_PUBLIC_URL
docker compose -p tabularium --env-file .env up -d --wait
```

网关只监听 `127.0.0.1`。前面要放一个 HTTPS 反向代理，满足三个条件：不缓冲响应（同步的变更流是长连接）；读取超时长于网关五分钟的连接上限；接受 64 MiB 的请求体。nginx 的写法：`proxy_buffering off`、`proxy_request_buffering off`、`proxy_read_timeout 600s`、`client_max_body_size 64m`。

安装插件：把 zip 中的 `main.js`、`manifest.json` 和 `styles.css` 复制到 `.obsidian/plugins/tabularium/`，然后启用。

## 备份与升级

`deploy/backup/cli.ts` 用 Node.js 24.10.0 运行，没有其他依赖：

```text
node deploy/backup/cli.ts backup   --compose <文件>... --env-file <文件> --project <名称> --output <目录>
node deploy/backup/cli.ts verify   <备份目录>
node deploy/backup/cli.ts restore  <备份目录> --project <名称> --target <目录> --port <端口>
node deploy/backup/cli.ts restore-scheduled <备份根目录> <备份点> --image <镜像> --compose <文件>... --env-file <文件> --project <名称> --target <目录> --port <端口>
node deploy/backup/cli.ts upgrade  --image <镜像> --compose <文件>... --env-file <文件> --project <名称> --output <目录>
node deploy/backup/cli.ts rollback <备份目录> --compose <文件>... --env-file <文件> --project <名称> --output <目录>
```

`backup` 短暂停止服务，归档两个数据卷和镜像。`upgrade` 先做这样一份备份，在副本上试运行新镜像，通过后再切换；`rollback` 回到升级前的那份备份。恢复总是进入一个新的 Compose 项目，从不覆盖正在运行的项目。定时备份由服务器自己写入，在「管理 → 备份」中配置。
